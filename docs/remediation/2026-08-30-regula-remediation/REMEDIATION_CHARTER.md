# Regula remediation charter

Date: 30 August 2026

## Product boundary

OBSERVED: `docs/ENGINEERING_ROADMAP.md` defines Regula as a local tool that
reports code-observable indicators for human review. It does not decide legal
applicability, legal classification, conformity or compliance. Absence of a
finding is not clearance.

This remediation will enforce that boundary across generated output, public
copy, integrations and examples. Observations, declared facts, missing or
contradictory context, source provenance and an empty human decision field must
remain distinct.

## Authorised work

- Inspect and modify product code, tests, generators, local documentation,
  website source and safe repository configuration needed for the bounded
  remediation.
- Create regression tests before or with each fix.
- Run local checks, browser tests, static checks and non-mutating source
  verification.
- Retain non-sensitive implementation and verification evidence in this dated
  directory.

## Prohibited work

- No commit, push, deploy, publish, release, upload, DNS change, external
  GitHub mutation, package publication, message, form submission or spending.
- No secret, credential, private record or personal-data access.
- No destructive worktree operation, history rewrite, bulk deletion, test
  weakening or gate bypass.
- No representative evaluation, participant research or autonomous legal
  determination.
- No new jurisdiction, framework, command, integration, dashboard, agent or
  speculative feature.

## Dirty-tree rule

All pre-existing changes are of unknown provenance unless direct evidence says
otherwise. Overlapping files must be read before editing. Existing intent will
be preserved through compatible incremental changes. No existing change will
be attributed to an owner, auditor or earlier agent without evidence.

## Phase order

1. Product-boundary contract and generated-output controls.
2. Configuration-correct and durable local cache.
3. Versioned assessment sharing with exact evidence preservation.
4. MCP, REST, workflow and feedback boundaries.
5. Multilingual website journey, trust shell and browser accessibility.
6. Evaluation-tooling schema readiness.
7. Repository-local release and reproducibility controls.
8. Full verification, challenge passes and final reporting.

## Stop conditions

Stop and report if safe progress requires a legal wording decision by counsel,
fluent legal-language approval, participant research, intrusive security
testing, external state mutation, secret access, a destructive operation, a
test or gate weakening, or an irreconcilable collision with pre-existing work.
