## Primary user and journey

INFERRED from the roadmap, README, CLI and existing public pages: the primary
user is a developer or governance reviewer deciding whether Regula is
appropriate for a repository, examining a truthful example, running a bounded
local workflow and preparing evidence for accountable review.

The implemented primary journey is:

1. Understand Regula as a local code-observation and evidence-preparation tool.
2. See which source-code indicators it can record.
3. See which legal, organisational and deployment facts it cannot know.
4. Inspect a result containing observations, unknowns and reviewer questions.
5. Understand that source stays local in the supported workflow.
6. Use the currently supported pinned source path or browser assessment.
7. Reach methodology, limitations, security, privacy and repository evidence.

## Implemented change and objective rationale

- The homepage now leads with one bounded task and one supported evaluation
  action. This reduces competing authority signals and makes the current
  source-only distribution explicit.
- A concrete evidence example shows an indicator, its source, unknown context,
  reviewer questions and an empty human decision. This demonstrates the actual
  product contract rather than relying on disclaimer placement.
- Browser results use the same review vocabulary as CLI and generated reports.
  Article 5, Article 6, Annex III and Article 50 no longer become completed
  legal decisions from matches or declared context.
- Share schema version 4 preserves unanswered, unsure, yes, no,
  not-applicable and contradictory states. Malformed and unsupported links
  show recovery messages instead of manufacturing a result.
- The shared site shell, metadata, navigation, locale links and coverage pages
  use consistent structure. Consequential metadata wording was included in
  the product-boundary control.
- The region generator source was corrected and all five controlled outputs
  regenerated. This removes change amplification from direct generated edits.
- Demonstrated recurring PT-BR diacritic errors were corrected and guarded.
  Fluent language and legal-meaning review remains external.

## Compatibility and remaining risk

The browser share format is versioned and legacy links remain explicitly
decodable, but old links are labelled lossy because their missing state cannot
be recovered. Public review schema 2.0 is intentionally incompatible with
consumers of the former legal-outcome object. Current live deployment,
canonical consumption, search caches and social previews were not inspected.

Conclusion: the website source is ready for local code review, not for a claim
of visual acceptance, accessibility conformance or bounded public evaluation.
