## Notes

- R1, R2, R3, R5, R6, R7, and R8 were resolved cleanly and defensively without breaking the architecture.
- R6, R7, and R8 were found via active Phase 5 threat-model investigation (not user-reported). R7 and R8 in particular were discovered through empirical, evidence-based stress testing of the actual pattern library and its runtime dependencies (CPython's `ast` module) rather than static/theoretical analysis — R8 especially was an unplanned discovery made while verifying the fix for R7, underscoring the value of testing fixes against real adversarial input rather than trusting the fix's own reasoning.
- R8 was subsequently found to affect 7 MORE call sites beyond the one originally fixed, discovered by deliberately following up on that fix's own documented limitation ("any code calling ast.parse() elsewhere... should be reviewed for the same gap"). Each additional site's reachability and real-world failure mode was independently verified by reproduction (not assumed from the shared root cause) before being fixed — in particular, `regula gap`'s failure mode (silent exit 0) was found to be worse than the originally-fixed site's (exit 2), and the cross-file-oversight path revealed that a bare `except Exception` elsewhere had been accidentally (not intentionally) providing partial protection.
- R7 and R8 both route through the existing skip-accounting/partial-scan machinery established for DEF-004/DEF-005 (R8's main-loop fix) or the identical graceful-degradation pattern applied consistently across all 8 sites, consistent with the program's practice of extending one well-tested mechanism rather than introducing parallel ad hoc handling per defect.
- Severity/priority reflect impact on the product's stated value (trustworthy,
  reproducible, safety-gating), not code volume. R8 is rated Critical (rather than High like R6/R7) because it is a full scan/command-availability failure (not merely a slowdown), reachable with a much smaller and more easily-produced trigger (~10 KB vs multi-MB), and was capable of silently discarding a genuine, already-detected finding in an unrelated file, or (in the `regula gap` case) silently producing no report at all while exiting successfully.
- R9 was found opportunistically while investigating scripts/api_server.py for network-facing hardening under this phase (which was found to already be well-designed: opt-in CORS, request-size limits, path-traversal checks, and an independently-added 1MB regex-DoS cap on /v1/classify predating this program's own DEF-006 finding). Rated Medium (lower than R5-R8) because it is a data-integrity/consistency defect in a machine-readable contract, not a scan-availability or code-execution-safety failure — but is still concretely exploitable by any real automation that trusts the documented, frozen envelope's own exit_code field over the process exit code.
